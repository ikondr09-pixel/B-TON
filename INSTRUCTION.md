# Инструкция по настройке отправки заказов в Google Таблицы с уведомлением на почту

## Что было изменено

Ранее заказы отправлялись через Telegram-бота. Теперь заказы:
1. Сохраняются в Google Таблицу (https://docs.google.com/spreadsheets/d/1ZNSjyMbDX6uhpPreP6522YEaKCQKpGm1j70_uP8d5w/edit)
2. Отправляют уведомление на почту bton.main@yandex.ru

## Файлы

- `index.html` - обновлённая функция отправки заказа (теперь использует Google Apps Script)
- `google_apps_script.js` - скрипт для Google Apps Script, который обрабатывает заказы

## Пошаговая инструкция по настройке

### Шаг 1: Откройте Google Таблицу
Перейдите по ссылке: https://docs.google.com/spreadsheets/d/1ZNSjyMbDX6uhpPreP6522YEaKCQKpGm1j70_uP8d5w/edit

### Шаг 2: Откройте редактор Apps Script
1. В меню выберите **Расширения** → **Apps Script**

### Шаг 3: Вставьте код скрипта
1. Удалите весь существующий код в редакторе
2. Скопируйте содержимое файла `google_apps_script.js`
3. Вставьте код в редактор Apps Script
4. Нажмите **Файл** → **Сохранить** (или Ctrl+S)

### Шаг 4: Разверните веб-приложение
1. Нажмите кнопку **Развернуть** (Deploy) → **Новое развертывание** (New deployment)
2. Нажмите на шестерёнку и выберите **Веб-приложение** (Web app)
3. Заполните поля:
   - **Описание**: B'TON Order Processing (или любое другое)
   - **Выполнять как**: Me (от вашего имени)
   - **У кого есть доступ**: **Все пользователи** (Anyone) - это важно!
4. Нажмите **Развернуть** (Deploy)
5. Разрешите доступ при запросе (Manage permissions → Выберите аккаунт → Advanced → Go to ... (unsafe) → Allow)

### Шаг 5: Скопируйте URL веб-приложения
После развёртывания вы получите URL вида:
```
https://script.google.com/macros/s/XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX/exec
```
Скопируйте этот URL.

### Шаг 6: Обновите index.html
1. Откройте файл `index.html`
2. Найдите строку (примерно строка 1287):
   ```javascript
   const scriptUrl = 'YOUR_GOOGLE_APPS_SCRIPT_URL';
   ```
3. Замените `'YOUR_GOOGLE_APPS_SCRIPT_URL'` на скопированный URL из Шага 5

### Шаг 7: Проверьте работу
1. Откройте сайт в браузере
2. Добавьте товары в корзину
3. Оформите заказ, заполнив форму
4. Проверьте:
   - Google Таблицу - должна появиться новая строка с данными заказа
   - Почту bton.main@yandex.ru - должно прийти уведомление

## Структура данных в таблице

Таблица будет иметь следующие столбцы:
- **A**: Дата (дата и время оформления заказа)
- **B**: Имя (имя клиента из формы)
- **C**: Контактные данные (телефон/email из формы)
- **D**: Комментарии (комментарий к заказу из формы)
- **E**: Заказ (список товаров с количеством и ценами, итоговая сумма)

## Примечания

- При первом заказе скрипт автоматически создаст заголовки таблицы
- Email уведомления приходят в HTML-формате
- Все данные сохраняются в часовом поясе, указанном в настройках скрипта

## Диагностика (сентябрь 2026): почему почта приходит, а таблица не обновляется

Проверено фактическими запросами к развернутому веб-приложению:

1. `GET .../exec` отвечает `{"status":"ok"}` → **развертывание живое, URL в index.html рабочий**, doPost тоже обрабатывается (письмо уходит).
2. В `google_apps_script.js` константа `SHEET_ID` НЕ совпадает с ссылкой на таблицу:
   - ссылка в инструкции: `1ZNSjyMbDX6uhpPreP6522YEaKCQKpGm1j70_uP8d5w` (43 символа);
   - в коде:               `1ZNSjyMbDX6uhpPreP6522YEaKCQKpGm1j70_uP8d5w` (42 символа — пропущен 1 символ).
   ID Google-таблицы чувствителен к каждому символу, поэтому `SpreadsheetApp.openById(SHEET_ID)` падает
   с ошибкой вида «The spreadsheet with id ... cannot be found», исключение «проглатывается» блоком
   `try/catch`, и скрипт возвращает success — визуально всё работает, кроме записи в таблицу.
3. Дополнительная возможная причина (если ID всё же верный): у таблицы нет доступа по этому ID для
   аккаунта, под которым опубликовано развертывание («Выполнять как: Me»), или лист удалён/переименован
   (`getActiveSheet()` тогда тоже бросит исключение).

**Что сделано в репозитории (без изменения развертывания и ссылки):**
- `index.html`: исправлена синтаксическая ошибка в `submitOrder` (незакрытая строка в `alert(...)`),
  из-за которой падал весь `<script>` и переставали работать ВСЕ кнопки; добавлен guard от дублирующихся `id` полей формы.
- `google_apps_script.js`: явная проверка формата `SHEET_ID` с понятной ошибкой, резервное сохранение
  заказов, не попавших в таблицу (`PropertiesService` + функции `dumpPendingOrders()` / `clearPendingOrders()`),
  текст ошибки записи возвращается в JSON-ответе (`sheetError`).

**Как исправить запись в таблицу (один из двух путей, без пересоздания веб-приложения по новому URL):**
- Путь А (рекомендуемый): откройте реальную таблицу, скопируйте её ID из адресной строки браузера,
  подставьте в `SHEET_ID`, затем «Развернуть → Управление развертываниями → ✏️ → Версия: Новая
  (максимальная) → Обновить». При обновлении существующего развертывания тип `/exec` URL НЕ меняется —
  править `index.html` не нужно.
- Путь Б: пока таблица недоступна, заказы не теряются — они копят в PropertiesService и выгружаются
  функцией `dumpPendingOrders()`, а письмо на почту продолжает приходить.

## Альтернативы Google Таблицам: уведомления на почту + автоматический учёт заказов

(Telegram-бот сознательно не предлагается.)

1. **Бесплатные form-сервисы с готовыми интеграциями**
   - **Formspree** (formspree.io): `<form action="https://formspree.io/f/XXXX" method="POST">` — письма на почту + панель Submissions + экспорт CSV; есть webhook на каждый заказ. Бесплатно ~50 заявок/мес.
   - **Getform, FormSubmit.co**: то же самое, FormSubmit умеет пересылать заявки на несколько адресов и хранить их.
2. **Airtable (или NocoDB / Baserow — open-source аналоги)**
   - Заказы пишутся в базу через REST API (`POST https://api.airtable.com/v0/<base>/<table>` с токеном),
     в Airtable настраиваются уведомления на email (Automations → «Send email»), интерфейс как у таблицы,
     но с историей, валидацией и статусами заказов. Прямой вызов из браузера раскрывает токен, поэтому
     лучше тонкий прокси (Cloudflare Worker / Vercel Function).
3. **Supabase (open-source Firebase-альтернатива)**
   - Таблица `orders` в Postgres + Row Level Security + Edge Function, которая пишет строку и шлёт письмо
     через Resend/SMTP. Дашборд вместо таблицы, бесплатного тарифа хватает с запасом.
4. **Self-hosted: Budibase / Appsmith / NocoDB**
   - Ставится на любой VPS (Docker), даёт внутреннюю БД заказов + SMTP-уведомления + форму/CRM без внешних сервисов.
5. **Собственный микросервис + база данных**
   - Небольшой backend (Node/Python) на VPS или Serverless (Cloudflare Workers + D1/KV, Vercel + Neon/Turso SQLite):
     принимает POST, пишет в PostgreSQL/MySQL/SQLite, шлёт почту через SMTP (Yandex Mail для домена) или Transactional API (Resend, Brevo, Mailgun, SendGrid). Полноценная замена связке Apps Script + Sheets.
6. **Tally / Notion-комбинация**
   - Форма Tally (бесплатно) → интеграция «Send email» + автозапись в базу Notion «Заказы» (Notion API / Make).
7. **Конструкторы сайтов/CRM**
   - Bitrix24 или amoCRM: веб-форма сайта отправляет лид в CRM, CRM сама шлёт уведомления на почту и держит список заказов.
8. **Промежуточный автоматизатор**
   - Make (Integromat) / Pabbly Connect / n8n (self-hosted): сайт → HTTP-модуль → «Записать в Airtable/Postgres» + «Отправить email». Один сценарий заменяет и Apps Script, и таблицу.

Минимальные усилия при текущем сайте: заменить `fetch(scriptUrl, ...)` в `submitOrder` на POST на Formspree
(учёт+почта «из коробки») или на свой Cloudflare Worker, который пишет в Airtable/Supabase и дублирует письмом.
